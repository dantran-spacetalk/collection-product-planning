Blog opening wrapper

Every blog post starts with this wrapper. Use a plain <div>, not an <article> tag: Shopify's blog template already renders its own <article> around the post, so nesting a second one is redundant.

  • .spacetalk-blog — required wrapper. Sets max content width, side padding, font and base text colour for everything inside.
<div class="spacetalk-blog">
  ... rest of the post content goes here ...
</div>

Intro / opening paragraph

This is the distinct opening excerpt, so it needs its own class. Normal paragraphs after it do not need a class.

  • .blog-excerpt — put this on the opening <p>.

For many Australian parents, location sharing isn't about monitoring every movement.

<p class="blog-excerpt">Your intro sentence goes here.</p>

Table of contents

Lists every <h2 class="blog-h2"> in the post as a jump link. Leave the block empty — blog-schema.js finds the headings, adds an id to any that don't have one, and builds the list.

  • .blog-toc — empty <nav>, placed near the top of the post.
  • Only .blog-h2 headings are listed. An <h2> without that class is skipped.
  • Optional: add your own <h2> inside to override the default "In this article" title.

In this article

  1. What to look for
  2. What to avoid
  3. Frequently asked questions

Body copy

No class needed — plain body <p> elements directly inside .spacetalk-blog are automatically styled as standard paragraph copy.

  • No class — just <p> as a direct child of .spacetalk-blog.
  • Need more space below something? See Spacing utilities.

Standard paragraph text sits at 17px with generous line height for readability.

<p>
  Your paragraph text goes here.
</p>

Headings

Bold <h2> with a light underline, used to divide the major sections of a post.

  • .blog-h2 — put on an <h2>.
  • Every .blog-h2 is automatically added to the table of contents. If you don't want a heading listed there, leave the class off.
  • <h3> — no class needed as a direct child of .spacetalk-blog. Use .blog-h3 when the h3 sits inside another block. Subheadings are never added to the table of contents.

Spacing utilities

Spacing is handled automatically on a three-tier scale, so related content groups together and sections stay distinct. You shouldn't need to adjust it by hand.

BetweenDesktopMobile
Paragraph and paragraph18px18px
Text and a block (image, row, list, table, quote)32px24px
Anything and a section heading48px32px

Block components use equal top and bottom margins, so the gap above a component always matches the gap below it. Adjacent margins collapse, so an 18px paragraph next to a 32px block gives 32px — never 50px.

Component margins use !important so they beat the theme's own styles. A side effect is that inline style="margin-bottom: 64px" no longer works — it gets ignored. Use these classes if you genuinely need to override the scale.

  • .blog-space-sm — 32px below
  • .blog-space-md — 48px below
  • .blog-space-lg — 64px below
  • .blog-space-none — removes the space below
<p class="blog-space-lg">Last paragraph before a product callout.</p>

<div class="blog-numbered-item blog-space-md">
  <h3><span class="blog-number-badge is-spacetalk-blue">7</span> Last point</h3>
  <p>Extra space before the next section.</p>
</div>

Image / Video

Matches the site's rounded corners (16px), no border. No class needed when it's a direct child of .spacetalk-blog.

  • No class — just <img> as a direct child of .spacetalk-blog.
  • A standalone <video> or <iframe> works the same way — also no class needed. Iframes get a 16:9 box automatically.
  • .blog-image — fallback class, only needed if the image sits somewhere else (not a direct child of .spacetalk-blog or .blog-media-row).

Media row (image or video + content)

Wraps a media element and a content <div> side by side on desktop, always matching each other's height. The media side can be an <img>, a <video> or an <iframe> (YouTube/Vimeo) — all three are styled identically and share the same left/right and width options. On mobile, the media always stacks first (on top) by default — no matter which side or width it's set to on desktop.

  • .blog-media-row — required wrapper.
  • .is-image-right — flips the media to the right on desktop (default: left).
  • .is-mobile-image-last — puts the media below the content regardless of desktop orientation on mobile screens.
  • .width-10 through .width-90 (steps of 10) — sets the media's share of the row on desktop, e.g. .width-30 = 30% media / 70% content. Ignored on mobile. Default with no width class is 50/50.
  • .align-top — content sits at the top of the row. This is the default, so you only need it if you want to be explicit.
  • .align-middle — content is vertically centred against the media.
  • Inside the content <div>: plain <h3> and <p> are styled automatically — no classes needed. Use <h3>, not <h2 class="blog-h2">, or the heading will be added to the table of contents.
  • For autoplaying video use autoplay muted loop playsinline — browsers block autoplay unless the video is muted.

Default layout: image on the left, content on the right, 50/50.

  • .blog-faq-item — put on each <details>.
  • Add open to a <details> if you want that question expanded on page load.

Auto-generated — don't add this yourself

The script reads each question/answer above and writes this for Google. Collapsed answers are still in the page, so Google reads all of them:

<script type="application/ld+json">
{ "@type": "FAQPage", "mainEntity": [
  { "@type": "Question", "name": "Question goes here?",
    "acceptedAnswer": { "@type": "Answer", "text": "Answer goes here." } }
] }
</script>

AI Prompt

Copy this and paste it into ChatGPT, Claude or Copilot along with your raw blog content. It teaches the model the whole system, so it can convert plain copy into correctly themed markup without you explaining the rules each time.

Always check the output. No prompt makes a model perfectly reliable — paste whatever it produces into the markup validator before publishing. It checks the rules mechanically, so it doesn't matter which model wrote the HTML.

You are formatting content for the Spacetalk blog. Convert the article I give you
into HTML using ONLY the component system below. Output raw HTML for the Shopify
blog post body - no <html>, <head> or <style> tags.

=== GOLDEN RULES ===
1. Wrap everything in ONE <div class="spacetalk-blog">...</div>
2. NEVER write font-family, font-size, colour or margin styles. The stylesheet
   handles all of it and uses !important, so inline styles are ignored anyway.
3. NEVER write JSON-LD / schema by hand. A script generates it automatically.
4. NEVER wrap an <img> in a <p>. Images must be direct children.
5. Only use the classes listed below. Do not invent new class names.
6. Spacing is automatic (18px between paragraphs, 32px around blocks, 48px above
   a section heading). Do not add spacing manually.

=== NO CLASS NEEDED (auto-styled) ===

<h3>               subheading (NOT added to the table of contents)
<img>              full-width rounded image
<video autoplay muted loop playsinline>   autoplaying video (muted is required)
<iframe>           YouTube/Vimeo embed, gets a 16:9 box
Only if an <h3> is nested inside a block that isn't a media row or numbered
item, add class="blog-h3" to it.
